# MagicConverter 3.0.0 예비 후보 성능 검증

이 기록은 공개 런타임으로 교체하기 전의 성능과 용량입니다. 배포본 수치는 [3.0.0 릴리스 검증](3.0.0.md)에 있습니다.

공개된 2.2.39 설치 파일에서 설치한 CLI, 초기 Rust 3.0.0 태그의 CLI, 최적화한 Rust 3.0.0을 같은 Windows 호스트에서 비교했다. 아래 표의 변환 시간은 CLI 시작부터 프로세스 트리 종료까지이며, 워밍업을 제외한 반복 측정의 중앙값이다. 설치·트레이·드래그는 같은 네트워크 차단 Windows Sandbox의 단일 비교이고, Python 대형 XLSX는 실측 1회다.

| 작업 | Python 2.2.39 | 초기 Rust 3.0.0 | 최적화 Rust 3.0.0 |
| --- | ---: | ---: | ---: |
| 기록 100건이 있는 프로필에서 작은 파일 복사·기록 | 1.001초 | 4.316초 | 0.082초 |
| 변환 경로 판정 43,650개 | — | 105.3ms | 79.5ms |
| XLSX 868만 셀 → PDF | 190.85초 | 20.94초 | 18.41초 |
| 이미지 5개 → PNG | 3.10초 | 0.21초 | 0.18초 |
| 이미지 3개 → AVIF | 2.43초 | 0.31초 | 0.21초 |
| PDF → 편집형 PPTX | 2.93초 | 0.260초 | 0.262초 |
| DOCX·XLSX·PPTX → PDF, 실제 Office | 16.08초 | 8.16초 | 8.52초 |
| 구형 PPT → PDF, 별도 순차 실행 | 5.89초 | 2.74초 | 2.80초 |
| WAV → FLAC, 동일 FFmpeg | 1.28초 | — | 0.34초 |
| MP4 → WebM, 동일 FFmpeg | 11.86초 | — | 11.44초 |
| MP4 → MKV 재포장, 동일 FFmpeg | 1.21초 | — | 0.23초 |

경로 탐색은 확장자와 입력 형식별 변환 후보를 미리 색인한다. 43,650개 판정의 출력은 개선 전후 바이트가 일치했다. 결과 기록은 버퍼를 거쳐 저장하며, 읽은 JSON을 다시 복제하지 않는다. 기록이 쌓인 시험에서 Windows Job의 쓰기 작업 수가 287,065회에서 373회로 줄었고, 기존 기록 100건과 신규 기록을 확인했다. 대형 XLSX는 PDF 파일 위치를 쓴 바이트 수로 추적한다. Rust의 6회 출력은 바이트가 같았고 Python과 Rust 모두 29,448쪽에서 8,681,985개 셀의 내용 해시가 일치했다. 최적화 Rust 출력은 약 69.8 MB, Python 출력은 약 87.1 MB였다. 동일 표본의 최대 작업 집합 표본은 Python 499 MiB, 최적화 Rust 중앙값 34 MiB였다.

공개 Python 설치본과 초기 Rust로 828개 대표 변환을 실행했다. 최적화 설치본도 동일한 828개를 실행했다. 첫 실행에서 Python TAR.ZST 압축 풀기가 Windows 접근 오류를 냈고, 최적화 Rust의 구형 PPT 변환은 다른 PowerPoint 시험과 겹쳐 거부됐다. 별도 폴더에서 TAR.ZST를 다시 풀어 양쪽 내용 해시를 대조했다. 구형 PPT는 PowerPoint 시험을 분리하고 세 빌드 모두 반복 성공했으며 PDF 렌더도 같았다. 재검증 반영 기준 양쪽 성공 813개, 양쪽 거부 10개, Rust만 성공 5개다. 이미지·미디어·문서·표·전자책·압축·자막·데이터·글꼴·3D·지리·메일을 반복 계측했다. 동일 FFmpeg 및 FFprobe로 직접 미디어 경로 258개의 출력 바이트 또는 디코딩 결과를 검증했다.

오프라인 설치는 Python 16.98초와 Rust 10.54초, 제거는 3.51초와 0.70초였다. 트레이 IPC 준비는 1.25초와 0.17초였다. OLE 시험에서 Shift 로컬 파일의 드롭부터 결과 생성까지 약 867ms와 32ms, Shift 웹 이미지는 740ms와 17ms였다. Ctrl 로컬 파일 복사는 22ms와 31ms였으며 휠 표시 시간은 두 빌드 모두 약 15ms였다. 이 UI 단일 표본은 약 10ms 간격으로 관찰했다. 폴더 감시와 로컬 IPC의 중복 방지, 재시작, 취소 및 MCP 후속 작업도 통과했다.

Rust가 모든 단일 시험에서 더 빠르지는 않았다. 초기 Rust와 비교하면 Office 배치 중앙값은 약 4.5% 길었고, 엔진을 통제한 720p WebM의 Python 대비 개선은 약 3.6%였다. 압축 ZIP은 약 136.8 MB이며 설치 후에는 약 462.3 MB를 사용한다. 출력과 품질에 영향을 주는 인코더 설정은 이번 최적화에서 바꾸지 않았다.
