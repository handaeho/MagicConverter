# MagicConverter

Windows 10/11용 오프라인 방사형 파일 변환·작업 도구. PySide6 기반 시스템 트레이 앱.

릴리스 빌드·입력 잠금·SBOM·오프라인 재현·CI 절차는
[docs/development/BUILD.md](../development/BUILD.md)를 참고하세요.
공개 배포 현황과 남은 검토 항목은 [공개 배포 기록](../release/OPEN_SOURCE_RELEASE.md)에 정리했습니다.

## EXE로 시작하기

Windows 10·11 64비트용 2.2.39 설치 EXE에 앱 전용 Python, 필수 라이브러리, FFmpeg·FFprobe와 rhwp가 들어 있습니다. 라이선스에 동의하고 폴더를 선택하면 인터넷 연결 없이 설치할 수 있습니다. [설치 안내](PUBLIC_WINDOWS.md#exe로-시작하기)

## CLI로 시작하기

설치 폴더에서 앱에 포함된 Python으로 CLI를 실행합니다. [명령어 예시](PUBLIC_WINDOWS.md#cli로-시작하기)

## 기본 사용

탐색기에서 파일 선택 → 드래그 중 키 유지 → 원하는 휠 슬롯에 파일 놓기.

| 키 | 기능 |
| --- | --- |
| Shift | 파일 형식 변환·이미지 압축 |
| Ctrl | 경로 복사·메타데이터 제거·ZIP 압축·파일 폴더에서 터미널 열기 |
| Esc 또는 보조키 해제 | 드롭 전 취소 |

두 키 동시 입력 시 Ctrl 우선. 변환 결과는 원본 폴더에 별도 파일로 저장.

ZIP 안의 파일을 바로 드래그할 때는 ZIP 우클릭 → **연결 프로그램 → Windows 탐색기**로 열고,
압축을 풀지 않은 목록에서 내부 파일을 드래그합니다. ZIP 아이콘을 끄는 작업과 구분하세요.
2.1.10 최종 앱의 탐색기 단일/다중 변환·ZIP 원본 보존 증빙을 유지합니다.
반디집에서는 Shift를 누른 채 놓으면 ZIP 내부 항목이 사라지는 사례가 확인됐습니다.
초기 2.2.0 후보의 반디집 실제 검사에서도 원본 소실·처리 오류가 확인됐습니다. 최신 빌드의
공급자별 판정은 [검증 기록](../development/VALIDATION.md)을 확인하세요. 설정 → 기본 →
**압축 프로그램 호환**은 다음 키 해제 동작을 제공합니다.

1. 파일 드래그 중 Shift로 휠을 표시합니다.
2. 원하는 슬롯 안에서 마우스는 계속 누른 채 **Shift를 먼저 놓습니다**.
3. **‘이제 놓으세요’ 표시와 활성 슬롯을 확인한 뒤** 마우스를 놓습니다. 회색이면 놓지 말고 Esc로 취소합니다.

기본값은 해제이며 기존 조작을 유지합니다. 선택 옵션은 키 해제 확인 전 Move/Drop을 거부합니다.
이 옵션은 시스템 임시 폴더 입력을 합계 32 MiB·100개까지
보존합니다. 지정한 출력 폴더가 없으면 다운로드/MagicConverter로 저장합니다.
반디집 자체의 빠른 드래그 설정은 바꾸지 않습니다. Shift를 누른 채 놓는 경로는 사용하지 마세요.

- 이미지·영상·음성·PDF·문서·슬라이드·스프레드시트·자막·압축 파일 지원
- PDF → DOCX의 표·병합 셀·이미지 복원 및 PDF → 편집형 PPTX의 개별 개체·표·데이터 편집 가능한 차트 복원
- 내장 FFmpeg·FFprobe와 rhwp를 사용한 미디어 및 일부 한글 변환

## 데이터·폰트·전자책·메일·전문 형식

JSON/JSONL/YAML/TOML/XML/CSV/TSV, TTF/OTF/WOFF/WOFF2, EPUB/FB2/CBZ,
EML/MHTML, OBJ/STL/PLY, WGS84 GeoJSON/KML/KMZ/GPX를 변환합니다.
파일을 드래그하면 해당 변환이 휠에 표시되며 프리셋·CLI·IPC·감시 폴더도 지원합니다.
메일 보관 ZIP에는 원본 EML·첨부파일·원래 이름/SHA-256 목록을 함께 저장합니다.

```powershell
.\runtime\python.exe .\app\run_magic_converter.py convert "자료.json" --to yaml --output "D:\결과"
.\runtime\python.exe .\app\run_magic_converter.py convert "글꼴.ttf" --to woff2
.\runtime\python.exe .\app\run_magic_converter.py convert "책.epub" --to fb2
.\runtime\python.exe .\app\run_magic_converter.py convert "메일.eml" --action email:attachments
.\runtime\python.exe .\app\run_magic_converter.py watch "D:\자료함" --to csv --include "*.json;*.xlsx"
```

XML 데이터 출력은 자료형 보존 컨테이너 또는 `$xml` 모델 복구입니다.
CFF→TTF, DRM 도서, MSG/MOBI/CAD 등은 지원 목록에서 제외합니다.
형식별 보존·손실·제한·배포 조건: [형식 계약](../reference/FORMAT_CONTRACTS.md).

## 감시 폴더·CLI·IPC·탐색기·웹 드래그

트레이 **감시 폴더 / 웹 드래그 / 탐색기…**에서 감시 폴더를 추가하고 프리셋·출력 폴더·포함 패턴
(`*.png;*.jpg`)·하위 폴더 여부·안정화 시간을 지정합니다. **규칙에 반영 → 저장·감시 시작** 순서로
적용합니다. 규칙에는 저장 시점의 프리셋을 복사하며, 이후 프리셋 변경은 규칙에 다시 반영해야 합니다.

- 기존 파일과 새 파일을 모두 검사합니다. 크기·수정 시간이 안정되고 Windows 작성 잠금이 풀린 뒤
  기존 파일별 작업 큐로 제출합니다. 주기적 재검사는 백그라운드에서 수행합니다.
- 임시 파일·링크·재분석 지점·출력 하위 폴더를 제외합니다. 감시 출력은 별도 하위 폴더 또는
  감시 루트 밖에 지정합니다. 원본은 이동·삭제하지 않습니다.
- 결과는 출력 폴더의 **`원본이름_이벤트해시/`** 안에 게시합니다. 페이지별 이미지 등 여러 결과도
  한 폴더로 완성한 후 게시합니다. SQLite 이력과 파일 해시가 든 영수증으로 재시작 후 중복을 막습니다.
  게시 직후 앱이 중단돼도 이미 완성된 폴더를 재사용합니다. 완료 출력의 사용자 삭제는 자동 복구하지 않습니다.
- **감시 중지·취소**는 새 제출을 멈추고 감시 작업을 취소합니다. 실패·취소 항목은 같은 내용으로
  반복 실행하지 않으며 **실패·취소 재시도**로 다시 처리합니다. 실행 중 강제 종료된 미완료 항목은
  다음 시작에서 복구합니다. 규칙/입력 내용이 바뀌면 새로운 이벤트로 처리합니다.

브라우저의 이미지·공개 파일 링크를 Shift/Ctrl 휠에 놓을 수 있습니다. 지원되는 data URL과 브라우저가
전달하는 이미지 데이터도 받습니다. 휠 표시 중에는 다운로드하지 않으며, 선택한 작업·프리셋·출력 위치를
고정하고 실행 시 받습니다. 서버가 준 파일명과 실제 헤더를 검사하며, 예상과 다른 엔진이 필요하면
변환을 거부합니다. 기본 출력은 **다운로드/MagicConverter**, 변경 위치는 자동화 창에 저장합니다.
다운로드 원본은 임시 파일이며 작업 종료 시 정리합니다.

HTTP/HTTPS 리디렉션은 최대 5회, 다운로드는 최대 512 MiB입니다. 응답/읽기 제한 15초,
무응답 제한 30초, 전체 다운로드 제한 10분을 적용하고 파일별 작업 제한도 유지합니다.
다운로드는 소유한 별도 프로세스에서 수행하여 취소 시 중단합니다. 로그인 쿠키는 전달하지 않으며
로그인 페이지·실행 파일·잘린 응답·용량 초과는 실패로 기록합니다. 로컬/웹 혼합 드래그, 웹 입력의
여러 파일 병합 작업, 브라우저 전용 가상 파일 스트림은 지원하지 않습니다.

**파일 선택해 변환…** 또는 탐색기 **MagicConverter로 변환…**는 파일과 작업을 검토하는 창을 엽니다.
자동화 창의 탐색기 메뉴 추가/제거는 현재 사용자에게만 적용하며 자동 등록하지 않습니다.
Windows 11에서는 **더 많은 옵션 표시**의 기존 메뉴를 사용합니다. 재실행/탐색기 요청은 실행 중인
앱에 전달하며, 여러 파일별 실행 요청은 같은 선택 창에 모읍니다.

## CLI로 시작하기

선택한 설치 폴더에서 아래 Python 명령을 실행합니다. MCP 전환은 후속 버전에서 진행할 예정입니다.

```powershell
# 직접 변환: --action 또는 --preset ID/이름, --to 형식 중 하나 선택
.\runtime\python.exe .\app\run_magic_converter.py convert --to jpg .\photo.png --output C:\Converted --json
.\runtime\python.exe .\app\run_magic_converter.py convert --preset pdf .\document.docx --report C:\Converted\result.json

# 감시: --once는 기존 안정화 파일 한 차례 처리, 생략하면 Ctrl+C까지 계속 감시
.\runtime\python.exe .\app\run_magic_converter.py watch C:\Inbox --action image:webp --include "*.png;*.jpg" --recursive

# 트레이 앱이 없을 때 사용할 별도 IPC/감시 서버
.\runtime\python.exe .\app\run_magic_converter.py serve
.\runtime\python.exe .\app\run_magic_converter.py status --json
.\runtime\python.exe .\app\run_magic_converter.py send --action document:pdf .\document.docx --request-id batch-001
.\runtime\python.exe .\app\run_magic_converter.py cancel 1 --instance STATUS에서받은ID
.\runtime\python.exe .\app\run_magic_converter.py stop --instance STATUS에서받은ID

# 탐색기 메뉴는 명시적으로 추가/제거
.\runtime\python.exe .\app\run_magic_converter.py shell install
.\runtime\python.exe .\app\run_magic_converter.py shell remove
```

`actions`, `formats`, `presets`로 지원 값을 조회합니다. 결과는 JSON이며 `--report`는 UTF-8 파일로
저장합니다. 종료 코드는 성공 0, 변환/다운로드/IPC 오류 1, 명령줄 구문 오류 2, Ctrl+C 130입니다.
`convert`는 독립 프로세스의 작업 큐를 사용하며, 실행 중 앱의 큐를 쓰려면 `send`를 사용합니다.
프로세스 간 결과 기록 저장은 잠금으로 보호합니다. `send`는 접수 응답이며 완료 여부는 `status`와
결과 기록으로 확인합니다. `--timeout`은 파일별 제한, `watch --retry`는 실패/취소 항목 재시도입니다.

각 명령과 GUI의 `--data-dir 경로`로 설정·감시 이력·IPC 채널을 분리할 수 있습니다. 같은 프로필의
감시 실행자는 하나만 허용합니다. IPC는 사용자 접근을 제한한 로컬 채널이며 요청 크기/연결 시간을
제한합니다. 최근 10,000개 요청 ID의 영수증을 유지합니다. 같은 ID/같은 내용의 재전송은 재실행하지
않고 기존 응답을 반환하며, 다른 내용은 거부합니다. 재시작 전 응답에는 `previous_instance`를 표시합니다.
취소·종료에는 현재 인스턴스 ID가 필요하므로 이전 작업 ID가 새 작업을 취소하지 않습니다.

자동화 설정은 `automation.json`, 감시 이력은 `watch-journal.sqlite3`, IPC 영수증은
`ipc-receipts.sqlite3`에 저장합니다. 읽을 수 없는 설정·미래 버전은 덮어쓰지 않습니다.
`--self-test`에 실제 CLI 변환·HTTP 실패 정리·IPC 중복 전달/재시작·새 창 렌더 검사를 추가했습니다.

## rhwp·문서 모델·Office 형식 확대

HWP ↔ HWPX 및 PDF 변환에는 내장 rhwp를 사용합니다. DOCX·PPTX·XLSX는
문서 모델로 HWPX를 작성한 뒤 rhwp로 HWP를 저장할 수 있습니다.
rhwp에도 파일별 취소·시간 제한·원자적 출력 정책을 적용합니다.

- 새 입력: **DOCM, DOTX, DOTM, PPTM, POTX, POTM, PPSX, PPSM, XLSM, XLTX, XLTM**.
  Word 계열은 DOCX, 슬라이드 계열은 PPTX, 시트 계열은 XLSX로 저장할 수 있습니다.
  VBA·ActiveX·포함 실행 개체는 변환 결과에서 제거하며 실행하지 않습니다.
- DOCX/HWPX 문서 모델에 수식을 추가했습니다. **분수·근호·위/아래 첨자**는 편집 가능한
  Office Math/한글 수식으로 옮깁니다. DOCX를 다시 DOCX로 저장할 때 원본 OMML을 유지합니다.
  지원하지 않는 수식 구조의 선형화는 경고하며, 모든 수식 문법의 완전한 왕복을 보장하지 않습니다.
- 표의 셀·병합 구조, 포함 그림 데이터, 수식 스크립트, 본문 텍스트를 변환 후 다시 읽어 비교합니다.
  차이나 검사 실패는 작업 결과·기록에 남깁니다. 원본 HWP의 개체 수는 바이너리 레코드에서도
  독립적으로 확인합니다. PDF는 페이지 구조를 검사하고 시각 확인이 필요한 원본 개체 수를 안내합니다.
- PPTX/XLSX → 한글 문서에서도 표·병합 셀·그림을 옮깁니다. 슬라이드 배치·차트·애니메이션과
  통합 문서의 인쇄 배치는 문서 모델과 다를 수 있습니다. Excel 수식은 문서에서 문자열로 표현합니다.
- 복합 문자 조판이 필요한 PDF는 rhwp 대신 기존 조판 엔진을 사용합니다. 글꼴·쪽 나눔·떠 있는
  개체의 완전한 시각적 일치는 보장하지 않습니다.

개발 환경의 rhwp 자산은 Python 3.14+로 `python tools/dependencies/fetch_rhwp.py`를 실행해 준비합니다.
다운로드 URL·SHA-256·라이선스는 [vendor/rhwp/BUILD.md](../../vendor/rhwp/BUILD.md)에 기록했습니다.
`--self-test`는 HWP/HWPX/DOCX 왕복과 PDF 렌더를 검사합니다.
`--self-test-office`는 설치된 Microsoft Office 연동도 검사합니다.

## 등록 기반 변환 경로

포맷 별칭과 변환 엔진을 등록하고, 최대 3단계의 변환 경로를 자동으로 찾습니다.
기존 단일 종류 휠과 작업 키는 유지하며, 서로 다른 종류의 파일을 선택하면
모든 파일에 가능한 공통 변환을 표시합니다. 예를 들어 PNG와 DOCX를 함께
드래그하면 각각 PDF로 내보낼 수 있습니다. 하나의 PDF로 묶으려면 Ctrl의 **PDF 병합** 도구를 사용합니다.

변환 요청은 실행 전에 모든 입력과 필요한 엔진을 확인합니다. 여러 단계가 필요한
슬라이드→PDF→PNG 같은 경로에서는 중간 파일을 전용 임시 폴더에 두고 최종 결과만
원본 옆에 게시합니다. 일반 변환기와 Office 작업 큐는 기존 실행 제한을 유지합니다.

핵심 모듈:

- `magic_converter/core/conversion/formats.py`: 포맷 ID, 확장자 별칭, 입력·출력 구분
- `magic_converter/core/conversion/conversion_catalog.py`: 변환기 계약, 엔진 상태, 최대 단계 수를 고려한 경로 탐색
- `magic_converter/core/conversion/builtin_converters.py`: 기존 변환기와 작업 정책 등록
- `magic_converter/core/conversion/conversion_request.py`: 파일별 경로와 실행 엔진을 고정한 변환 요청
- `magic_converter/core/conversion/conversion_execution.py`: 기존 인코더 연결 및 중간 결과 정리

변환기 추가 시 포맷과 직접 변환 경로를 등록하고 `Converter` 계약을 구현합니다.
페이지별 이미지 폴더처럼 여러 결과를 만드는 경로는 마지막 단계로 제한하고,
PDF→고정/편집 PPTX는 직접 요청한 PDF에만 사용합니다.
Filee 참조 커밋과 MIT 고지는 `docs/legal/THIRD_PARTY_NOTICES.md` 및 `licenses/Filee-MIT.txt`에 기록했습니다.

## 파일별 작업 관리

여러 파일은 파일별로 대기·실행하며, 한 파일이 실패하거나 시간을 초과해도 나머지는 계속
처리합니다. 일반 작업은 최대 2개, Office은 최대 1개를 실행하고 각 엔진의 동시 실행
한도도 적용합니다. 여러 단계를 거치는 파일은 필요한 엔진을 함께 확보한 뒤 시작하므로
엔진 대기로 작업 스레드를 점유하지 않습니다. 큰 배치 중에도 나중에 들어온 작업에 차례를 줍니다.

트레이의 **작업 관리…**에서 파일별 상태를 확인하고 **선택 파일 취소**, **선택 작업 취소**,
**모두 취소**를 사용할 수 있습니다. ZIP 하나로 묶는 작업은 선택한 파일 전체가 함께 취소됩니다.
배치의 결과와 출력 목록은 입력 순서를 유지하며, 진행률은 실제 완료·실행 파일을 합산합니다.

파일 처리 제한은 실행 시점부터 기본 1시간이며 대기 시간은 포함하지 않습니다.
FFprobe는 30초, Office/LibreOffice는 180초, FFmpeg는 10분간 출력이 없으면 중단합니다.
외부 엔진은 Windows 작업에 연결한 뒤 실행하고, 취소·시간 초과 시 소유한 프로세스 트리를
종료합니다. 이미지·PDF·표·압축의 반복 처리와 렌더러 잠금 대기에도 취소·시간 검사를 적용합니다.
실행 중인 네이티브 라이브러리 호출은 반환 후 다음 검사 지점에서 중단되며, Python 스레드를
강제 종료하지 않습니다. 완성본을 게시하기 직전에도 취소·시간을 확인합니다.

개발 API는 `ConversionService.cancel_file(job_id, file_index)` (1부터 시작),
`cancel_job(job_id)`, `cancel_all()`, `job_snapshots()`를 제공합니다.
생성자의 `parallelism`, `file_timeout`으로 실행 수와 파일 제한 시간을 조정할 수 있습니다.
`--self-test`는 등록형 작업 큐, 다단계 출력, 자식 프로세스 취소, 작업 관리 창도 검사합니다.

## 프리셋·휠 프로필·출력·기록

트레이 **실행 상태 / 설정…**에서 다음 항목을 편집하고 **저장·트레이 이동**을 누릅니다.

- **프리셋**: 작업 선택, 이름 변경, 추가·복제·삭제. 이미지 품질/긴 변, 영상 CRF,
  오디오 비트레이트와 프리셋별 출력 설정을 저장합니다. 지원하는 작업의 옵션만 활성화됩니다.
- **휠 프로필**: Shift/Ctrl 휠을 각각 선택합니다. 기본값은 기존 파일 종류별 자동 휠입니다.
  사용자 프로필은 프리셋 1~12개를 지정하며 드래그로 순서를 바꿉니다. 지원하지 않는 파일의
  슬롯은 이유를 표시하고 비활성화합니다. 프리셋을 삭제하면 프로필 참조도 정리됩니다.
- **출력·기록**: 원본 폴더 또는 지정 폴더, 이름 템플릿, 이름 충돌 정책을 설정합니다.
  `{stem}`은 원본 이름, `{tag}`는 converted/slide/editable/copy, `{preset}`은 프리셋 이름이며
  확장자는 자동으로 붙습니다. 충돌 시 번호를 붙이거나 해당 파일을 실패로 기록하며 기존 파일은 보존합니다.

프리셋·출력 설정은 드래그를 시작할 때 고정됩니다. 설정을 바꿔도 표시된 슬롯의 순서와 옵션이
드롭 시 바뀌지 않으며, 대기 중인 작업에도 제출한 값이 유지됩니다. 파일 목록이 드롭 직전에 달라지면
실행을 거부합니다. 실행 전 엔진 사용 가능 여부는 다시 확인합니다.

설정은 Qt `AppLocalDataLocation`의 `settings.json`에 버전과 함께 저장합니다.
첫 실행 시 기존 QSettings 값을 이전하고, 기본 동작 값은 기존 저장소에도 반영합니다.
저장은 임시 파일에서 교체하며 마지막 정상 파일은 `settings.json.bak`에 보관합니다.
손상되거나 누락된 파일은 백업으로 복구하고 손상본은 별도 보존합니다. 백업도 없으면 기본값을
사용합니다. 더 최신 버전 설정은 덮어쓰지 않습니다. **설정 가져오기·내보내기**, **백업 복구**,
**기본값 복원**을 제공하며, 가져오기·복구는 저장 버튼 전까지 편집 내용에만 적용됩니다.

트레이 **결과 기록…**에서 파일별 완료·실패·취소·시간 초과, 경로·오류·경고, 실행한 옵션을
확인하고 출력 폴더를 열 수 있습니다. `history.json`에 기본 최근 200개 작업을 저장하며
0으로 설정하면 새 기록을 저장하지 않습니다. 기록 삭제는 출력 파일에 영향을 주지 않습니다.
기록은 로컬 경로와 결과만 보관하며 파일 내용은 저장하지 않습니다. 설정 내보내기에는 기록이 포함되지 않습니다.

## PDF·이미지·미디어·자막·압축 도구

기본 **Ctrl 액션 휠**은 선택한 파일에 맞는 도구를 기존 네 가지 액션 뒤에 표시합니다.
Shift의 기존 변환 배치는 유지합니다. 사용자 액션 프로필을 사용하는 경우 설정의 프리셋에서
작업을 선택하고 **도구 옵션…**을 편집한 뒤 해당 프로필 슬롯에 추가합니다. 기본 휠은 기본 옵션으로
즉시 실행하며, 사용자 프리셋은 저장한 옵션으로 실행합니다.

| 종류 | 도구 | 옵션·결과 |
| --- | --- | --- |
| PDF | 병합 | PDF·이미지의 모든 페이지/프레임을 입력 순서대로 PDF 하나로 병합 |
| PDF | 페이지 추출·분할 | `1-3,5`, `3,1`, `3-1`처럼 순서 지정 · 빈 값은 전체 · 중복은 첫 위치 유지 |
| PDF | 회전·무손실 압축 | 선택 페이지만 0/90/180/270도 회전 · 내용 스트림/중복 객체 정리, 커지면 원본 내용 복사 |

PDF 병합은 전체 선택을 함께 완료·취소합니다. 다른 도구는 파일별로 처리합니다.
모든 결과는 기존 큐·취소·시간 제한·출력 이름·충돌 정책·결과 기록을 사용합니다.
자막 시작이 음수면 0으로 맞추고, 0초 이전에 끝나는 구간은 경고와 함께 제외합니다.
VTT에서 SRT로 변환하면 지원되지 않는 위치 정보는 경고와 함께 제외합니다.

이미지 도구는 GIF/APNG의 프레임·시간과 APNG 기본 이미지를 유지합니다. 같은 그림의 TIFF
페이지도 별도 프레임으로 남깁니다. 이미지 변형은 전체 1억 2,800만 프레임 픽셀까지 처리하며,
프레임 추출은 순차 디코딩합니다. 프레임 추출은 기본 최대 10,000개, 설정으로 최대 100,000개이며
초과하면 전체 임시 결과를 정리하고 실패로 기록합니다.

압축은 링크/장치·상위/절대 경로·Windows 예약 이름·대소문자 충돌·중복 파일을 거부합니다.
최대 100,000개 항목, 총 해제 크기 4 GiB를 검사하고 최소 64 MiB의 디스크 여유를 확인합니다.
암호화 ZIP/RAR은 지원하지 않습니다. RAR은 기존 재압축만 제공하며 새 해제 도구에는 포함하지 않습니다.

설정 JSON 버전은 2입니다. 3단계의 버전 1 설정은 자동 이전하며 기존 프리셋과 프로필을 유지합니다.
구버전 앱이 새 설정을 덮어쓰지 않도록 버전을 구분하고 마지막 정상 백업을 남깁니다.
`--self-test`는 15개 도구를 실제 파일로 실행해 PDF 페이지·렌더링, 이미지 프레임·시간,
미디어 전체 디코딩·스트림·프레임, 자막 시각, 압축 내부 바이트와 도구 UI를 검사합니다.

### 2.2.2 Office 연결

PowerPoint가 실행 중이면 해당 문서·설정을 유지하고 새 변환을 거부합니다. 저장 후 직접 종료한 뒤 다시 변환하세요.
새 PowerPoint는 빈 상태부터 제한된 작업에서 시작합니다.

### 2.2.3 PDF CJK 편집

긴 CJK 줄은 원본 위치에 맞춘 여러 짧은 텍스트 상자로 나뉠 수 있습니다. PowerPoint 내보내기의 작은 간격 반올림이
줄 끝까지 누적되는 현상을 줄입니다. 영문 단어·결합 문자와 짧은 줄은 나누지 않습니다.
미설치 글꼴·복잡한 효과는 기존처럼 그림으로 보존될 수 있으며, 완전한 원본 조판 일치를 보장하지 않습니다.

### 2.2.4 PDF 표의 줄 위치

줄 간격과 위쪽 여백을 원본에서 확실히 확인할 수 있는 표 셀은 저장된 기준선에 맞춰 배치합니다.
표는 편집 가능한 셀로 유지됩니다. 밀집된 줄·회전 글자나 모호한 위치는 기존 배치 경로를 사용하며 차이가 남을 수 있습니다.
표의 모든 글꼴·글리프·효과와 HWPX 대체 조판이 원본과 완전히 같다는 뜻은 아닙니다.

### 2.2.5 PDF 글자 모양과 밀집 표

늘이거나 윤곽선을 그린 일부 글자는 원래 모양의 도형 그룹으로 보존합니다. 그룹을 함께 이동·삭제할 수 있고 문자 내용의 편집은 제한됩니다.
일반 텍스트와 표 셀의 편집은 유지합니다. 밀집 표도 글꼴 상자가 들어가는 범위에서 기준선을 복원하며, 복잡한 효과·모호한 셀은 기존 보존 경로를 사용합니다.

### 2.2.6 반투명 글자 보강

늘이거나 윤곽선을 그린 일부 반투명 PDF 글자를 원래 모양과 투명도의 도형 그룹으로 보존합니다. 일반 반투명 텍스트의 문자 편집은 유지합니다.
도형이 많은 PDF는 반복 ID 검색을 줄여 처리하며, 복잡하게 겹치는 효과는 기존 그림 보존을 유지합니다.

### 2.2.7 겹친 글자·조밀한 표

겹치는 반투명 채움 글자는 진하기를 유지하는 개별 윤곽 도형으로 보존한다(문자 편집 제한). 표의 줄 간격을 셀 문단으로 표현할 수 없을 때는 표 격자·병합을 유지하고 해당 셀 글자를 표 위의 독립 텍스트 상자로 배치한다. 이 경우 셀 내부에서 글자를 수정할 수 없다는 안내가 나온다. 일반 셀은 기존 셀 내부 편집을 유지한다. 복합 그룹·마스크·부분 클립은 원래 모양 보존 경로를 유지한다.

겹치는 반투명 stroke는 합성·연결 모양 차이가 있어 기존 원래 영역 재생을 유지한다. 채움 곡선과 같은 규칙으로 도형화하지 않는다.

### 2.2.8 PDF 획 보존

반투명 획이 겹치거나 글리프가 비균등하게 변형된 경우 획 윤곽을 채움 도형으로 보존한다. 글자 편집은 제한되며 곡선 도형으로 편집·삭제할 수 있다. 단순 획과 일반 표 편집은 유지한다. HWPX 변환 엔진은 시스템과 사용자 글꼴을 사용하며 원래 글꼴·조판·PDF 원점의 완전 일치를 보장하지 않는다.

Excel PDF 자동화의 시작 복구 안내에 의한 연결 실패를 보강했다. 사용자 복구 기록을 지우지 않으며 전용 제한 프로세스에서 변환한다.

획이 자체 교차하는 부분의 작은 빈틈을 막도록 채움 영역도 합친다. 정밀도는 원본 PDF와 확인해야 한다.

### 2.2.9 PDF 복합 효과

분리된 투명 그룹의 내부 효과는 해당 그룹의 배경과 함께 보존하며, 그룹 바깥 배경은 개별 편집·삭제할 수 있다. 효과 자체는 여전히 그림으로 보존한다. 비분리 블렌드에 필요한 연결 배경은 한 그림에 포함된다.

### 2.2.10 PDF 클립 보존

완전히 가려진 글자 때문에 무관한 제목까지 전체 그림이 되던 경우를 복구한다. 부분 클립·Type3 모양과 소프트 마스크는 원래 재생으로 보존한다. 원래 해석으로도 순서를 대조할 수 없거나 복잡도 예산을 넘으면 전체 쪽 그림과 편집 제한 안내를 유지한다. HWPX 출력의 글꼴과 원점은 달라질 수 있다.

### 2.2.13 겹친 PDF 글자 보존

윤곽 도형으로 복원하는 불투명 글자들이 겹칠 때 획에 구멍이 생기던 경우를 고쳤습니다. 이 글자들은 문자 입력 대신 윤곽 도형으로 편집할 수 있습니다. 복잡한 마스크·Type3와 일부 글꼴·표의 정밀 복원 제한은 남아 있습니다.

2.2.13은 직선 윤곽의 커닝 교차부를0.25pt 이상까지 보완하고, 단일 검정 볼록 Type3 모양을 편집 가능한 도형으로 복원합니다. 복잡한 효과·부분 클립·마스크는 원래 모습으로 보존합니다. 좁은 단일 행 표는 글자 기준선을 보존하고 빈 문단 때문에 행이 늘어나지 않도록 했습니다. HWPX 실제 글꼴·국소 간격·약12pt 원점 차이는 남아 있습니다. 원격 CI는 현재 작업에서 제외했습니다.


## 2.2.14 보강

검증된 단색 볼록 Type3의 원래 곡선은 PPTX 편집 도형으로 보존합니다. 반복·복합 윤곽, 마스크·부분 클립·색 효과는 원래 모습으로 보존합니다. HWPX PDF 변환은 시스템과 사용자 글꼴을 읽으며 글꼴을 새로 설치하거나 복사하지 않습니다. 모든 PDF 효과의 편집 가능성, 기존33쪽의 로마숫자·간격·원점 동일성은 보장하지 않습니다. 자세한 현재 상태는 [후속 현황](../reviews/FOLLOWUP_RESOLUTION.md)을 확인하세요.


## 2.2.15 보강

단순한 오목·구멍·분리 Type3 글리프도 편집 도형으로 복원합니다. 모호한 교차·마스크·부분 클립은 원래 모습으로 보존합니다. HWPX의 굴림·휴먼명조가 없는 Ⅺ·Ⅻ는 실제 시스템 또는 사용자 영역의 대체 글꼴을 확인한 경우 해당 문자만 처리하며 변환 경고로 알립니다. 글꼴을 설치/복사하거나 원본을 수정하지 않습니다. 일반 간격·복잡한 효과와 native 출력 원점 차이의 완전한 복원은 남아 있습니다.


## 2.2.16 보강

안전한 곡선 구멍·섬·분리 Type3도 편집 도형으로 복원합니다. 불확실한 곡선·마스크는 원래 모습으로 보존합니다. HWPX 모델의 언어별 자간·장평과 DOCX 장평을 보존하며, 비율 자간과 Word 고정 pt 자간의 변환 손실을 알립니다. 글꼴별 실제 간격·전체 조판·native 원점의 완전한 동일성은 보장하지 않습니다.

## 2.2.17 보강

넓은 곡선 구멍과 렌즈 안의 구멍도 모양이 명확한 경우 원래 곡선을 편집 도형으로 보존합니다. 복잡한 마스크는 원래 모습으로 유지합니다. DOCX↔HWPX 변환에서 문단 좌우·첫줄 들여쓰기와 문단 앞뒤 간격이 사라지던 문제를 고쳤습니다. 모든 글꼴 간격·줄 조판과 장치별 출력 원점의 완전한 동일성은 남은 제한입니다.

## 2.2.18 보강

안전성이 확인된 비볼록 단일 곡선과 일정 농도 마스크의 단일 글리프도 윤곽 도형으로 편집할 수 있습니다. 복잡한 효과는 원래 모습으로 보존합니다. DOCX 고정 자간을 읽고 쓰며, 실제 글꼴에서 같은 폭이 확인되는 한글 구간은 HWPX 자간과 왕복합니다. 영문·복합 문자·혼합 폭 등 확인되지 않은 환산은 손실 경고를 유지합니다. 기본 프린터를 바꾸거나 출력 전체를 임의로12pt 이동하지 않습니다.


## 2.2.19 보강

서로 닿지 않는 중첩·분리 비볼록 Type3 곡선과 같은 농도의 사각형들로 빈틈없이 덮인 마스크도 안전성을 확인한 경우 편집 도형으로 보존합니다. 부분 클립과 불확실한 효과는 원래 모습으로 재생합니다. 동일 폭 한글의 자간 환산은 반올림 오차가 긴 문장에서 누적되지 않도록 처리합니다. 영문·복합 문자·혼합 폭 등 확인되지 않은 환산은 손실 경고를 유지합니다.

대용량 XLSX를 PDF로 변환하면 모든 시트의 값과 수식 문자열을 셀 주소가 붙은 목록으로 순서대로 출력합니다. 16MiB 이상 또는 선언된 행 수100000 이상인 파일에 적용됩니다. 빈 행은 생략합니다. 긴 문자열은 잘라 버리지 않고 `셀주소+계속번호`로 이어 씁니다. 원래 인쇄 배치·셀 서식·도형은 보존하지 않습니다. 이 제한은 완료 결과의 경고에도 표시됩니다. 작은 통합 문서의 기존 Excel 인쇄 경로와 구분됩니다.

실제40MB·667,845행 입력은30분 기한 검사에서 시간 초과됐습니다. 기본 파일별 기한은3600초이며 CLI에서는 `--timeout 3600`으로 지정할 수 있습니다. 시간 초과·취소 결과는 변환 성공과 구분하며 불완전한 PDF를 게시하지 않습니다. 현재 소스·EXE 실측과 내용 대조 결과는 [검증 기록](../development/VALIDATION.md)을 참고하세요.

아랍어·히브리어 등 복합 문자는 글자 모양과 원문 텍스트를 함께 보존합니다. PDF 뷰어·추출 도구의 대체 텍스트 지원에 따라 복사·검색 순서가 달라질 수 있습니다.

## 2.2.20 보강

대용량 Excel의 셀 목록은 같은 글자 크기로3~6단을 선택해 짧은 값이 많은 페이지를 더 조밀하게 출력합니다. 셀 주소와 긴 셀의 계속 번호를 유지하며, 내용에 따라 페이지 수가 줄어들지 않을 수도 있습니다. 원래 인쇄 배치·서식·도형을 보존하지 않는 제한은 같습니다.

일정 농도 마스크 아래 여러 글리프가 서로 충분히 떨어져 있으면 편집 가능한 윤곽 도형으로 복원합니다. 겹치거나 닿는 글리프, 가변 효과와 부분 클립은 원래 모습으로 보존합니다. 현재 실행 파일·실측·남은 제한은 [검증 기록](../development/VALIDATION.md)을 확인하세요.

## 2.2.21 보강

TXT→MD는 다른 문서 앱이 처리 중일 때도 일반 큐에서 실행됩니다. 글꼴과 레이아웃 엔진 초기화를 건너뛰며 기존 인코딩 판별과 UTF-8 출력을 사용합니다. DOCX의 문자·문단 스타일과 문서 기본값에 지정한 자간·장평을 읽습니다. HWPX 자간 환산의 글꼴·문자 제한은 기존과 같습니다.

일정 농도 PDF 마스크의 편집 윤곽 복원에서 실제로 그림을 그리지 않는 공백은 제외합니다. 공백 문자에 그림이 있는 글꼴은 그 윤곽을 유지합니다. 가변 마스크·부분 클립은 원래 모습으로 보존합니다.

## 2.2.22 보강

DOCX↔HWPX에서 굴림체·돋움체 정체의 ASCII 반각 문자와 완성형 한글이 섞인 자간을 실제 설치 글꼴의 글자 폭으로 환산합니다. 다른 비례 글꼴이나 복합 문자에 확인되지 않은 환산이 필요하면 손실 경고를 표시합니다.

PDF→편집형 PPTX에서 직사각형 클립으로 잘린 단일 볼록 직선 글리프는 보이는 부분을 편집할 수 있는 윤곽 도형으로 복원합니다. 곡선이나 복합 효과는 원래 모습으로 보존합니다.

## 2.2.23 보강

검증된 Tahoma 보통 글꼴의 영문 대문자·숫자·공백으로 구성되고 커닝이 없는 문단에서 DOCX↔HWPX 자간을 글자 폭에 맞춰 환산합니다. 글꼴 파일이 다르거나 문단에 다른 글자 조판 조건이 있으면 기존 손실 경고를 적용합니다.

PDF→편집형 PPTX에서 같은 직사각형 클립으로 잘린 여러 볼록 직선 윤곽도 충분히 떨어져 있으면 편집 가능한 도형으로 복원합니다. 근접하거나 겹친 윤곽, 곡선 등은 원래 모습으로 보존합니다.

## 2.2.24 보강

대형 Excel의 셀 목록 PDF를 저장할 때 누적 PDF를 병합하는 횟수를 줄였습니다. 검증된 Tahoma 보통 글꼴의 일부 소문자까지 자간 환산 범위를 넓혔습니다. 직사각형 한 변에 잘린 단일 볼록 베지어 윤곽을 편집형 PPTX에서 곡선 도형으로 복원합니다.

## 2.2.25 Excel 인쇄 영역 PDF

Excel에서 표시 워크시트마다 직사각형 인쇄 영역 하나를 저장하고 **PDF (Excel 인쇄)**를 선택합니다. Excel이 설치되어 있어야 합니다. 워크시트 최대 20개와 인쇄 영역 합계 10,000셀까지 지원하며, 반복 인쇄 행·열과 차트 전용 시트가 있으면 오류를 반환합니다. 대형 통합 문서의 전체 셀 값과 수식 문자열은 기본 PDF 메뉴에서 출력합니다.

```powershell
.\runtime\python.exe .\app\run_magic_converter.py convert .\report.xlsx --action office:xlsx_print_pdf --output .\out --timeout 180 --json
```

## 2.2.26 인쇄 영역 확장

표시 워크시트마다 겹치지 않는 직사각형 인쇄 영역을 두 개까지 저장할 수 있습니다. 영역을 하나만 저장한 시트에서는 그 영역 안의 연속된 행·열을 페이지마다 반복할 제목으로 지정할 수 있습니다. 같은 시트에서 인쇄 영역 두 개와 반복 제목을 함께 지정하면 오류를 반환합니다.

## 2.2.27 자동 인쇄 영역과 차트 시트

인쇄 영역을 저장하지 않은 시트에서는 값·수식의 직사각형과 Excel 사용 범위가 일치할 때 기본 인쇄 설정을 사용합니다. 범위 밖 서식, 병합, 도형, 인쇄 주석이나 반복 제목이 있는 시트에는 인쇄 영역을 저장해야 합니다. 저장 영역의 위쪽 행이나 왼쪽 열도 반복 제목으로 쓸 수 있고, 영역 두 개에 같은 제목을 적용할 수 있습니다.

일반 워크시트에 섞인 표시 차트 시트는 한 개까지 출력합니다. 워크시트 인쇄 영역과 추가 제목 셀의 합계는 20,000셀까지입니다.

## 2.2.28 Excel 인쇄와 PDF 편집

한 시트에 겹치지 않는 직사각형 인쇄 영역을 세 개까지 저장할 수 있습니다. 반복할 제목은 각 영역 안이나 위쪽·왼쪽에 두세요. 인쇄 영역과 추가 제목을 합쳐 통합 문서당 30,000셀까지입니다. 자동 영역은 이전 조건을 충족하면 회전하지 않은 표시 직사각형 도형 한 개도 포함합니다. 표시 차트 시트는 두 개까지 출력하며 차트만 들어 있는 통합 문서도 출력할 수 있습니다. Excel 인쇄 메뉴에는 Microsoft Excel이 필요합니다.

편집 가능한 PPTX로 바꿀 때, 직사각형의 인접 두 변에 잘린 일부 볼록 곡선은 이동하거나 삭제할 수 있는 도형으로 복원됩니다. 그라데이션 마스크 등 같은 방식으로 복원할 수 없는 영역은 원래 모습에 가깝게 유지합니다.
